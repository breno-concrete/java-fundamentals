## Fase 1 · Teoria (~40 min)

Um conceito por passo, cada um com um "Sua vez".

- [x] **Passo 1: array de buckets.** Chave diz a gaveta, `get` vai direto. *Sua vez: 7 → bucket 3, `get(5)` → bucket 1. Acertou.*
- [x] **Passo 2: do `hashCode` ao índice.** `hashCode` pode ser qualquer `int`, inclusive negativo, e precisa virar um índice entre 0 e n-1. *Sua vez: 13 → bucket 1; `-6 % 4` = -2, `floorMod(-6, 4)` = 2. Acertou, e perguntou sozinho sobre colisão (passo 3).*
- [x] **Passo 3: colisões.** Duas chaves na mesma gaveta: a gaveta vira lista e o `equals` acha a chave certa. *Sua vez: `get(7)` chama `equals` 2 vezes; `get("BB")` devolve 2. Acertou. Ajuste de vocabulário: "encadeados", não "aninhados"; "mesmo bucket", não "mesma chave".*
- [x] **Passo 4: load factor e resize.** Quando `size > capacidade × 0.75`, dobra o array e redistribui tudo (rehash). *Sua vez: 5, 9, 13 → bucket 1, sem resize (3 não é > 3); `put(1)` → resize para 8, ficam em 5, 1, 5, 1. Acertou.*
- [x] **Passo 5: bucket que vira árvore (Java 8+).** Lista que passa de 8 nós (com capacidade ≥ 64) vira árvore rubro-negra, o pior caso vai de O(n) para O(log n). Só teoria, não entra no lab. *Sua vez: 16 buckets → resize, não árvore. Acertou. 1024 chaves: respondeu O(n) / O(log n); faltou o número (1024 vs ~10).*
